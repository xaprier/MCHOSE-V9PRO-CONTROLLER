# Patchbay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Patchbay" page that shows PipeWire audio nodes, ports and links live and lets the user
connect/disconnect them by drawing cables, with optional (default off) restoring of user-made links.

**Architecture:** `pw-dump -m -N` feeds a pure graph-state class (tested) owned by a `PipeWireGraph`
QObject that exposes QML-friendly lists and runs `pw-link`. Restore rules are a pure matching function
(tested). QML draws boxes with a `Repeater` and cables with one `Shape`.

**Tech Stack:** C++20, Qt 6.8+ (Core, Qml, Quick, QuickControls2), QtTest, PipeWire CLI tools.

**Spec:** `docs/superpowers/specs/2026-10-30-patchbay-design.md`

## Global Constraints

- No new library dependency; PipeWire only via `pw-dump -m -N`, `pw-link <out> <in>`, `pw-link -d <link>`.
- No blocking I/O on the GUI thread (`QProcess` async only).
- Audio only: skip nodes whose `media.class` lacks `Audio`, ports whose `format.dsp` contains `midi`.
- "Restore links" setting key `patchbay/restore`, default **false**.
- Internal nodes: `node.name` starts with `v9pro_`; deleting a link touching one needs confirmation;
  restore never links two internal ports.
- User-visible strings in `qsTr()`; colours/spacing only from `Theme`.
- Commits: one line, `feature:`/`fix:`/`test:`/`docs:`, no body, no co-author.

## Review Focus

- `pw-dump` output split across reads mid-object, or several arrays in one read → parser must buffer
  and emit each complete top-level array exactly once (test in Task 1).
- Object removal (`"info": null`) for a node must also drop its ports and links (test in Task 1).
- Same node key appearing twice (two Zen streams) → a rule links both; positions don't collide
  (test in Task 2; occurrence index in Task 3).
- `pw-dump` killed/exits → graph cleared and process restarted after 2 s, UI shows empty state not stale
  boxes (Task 3 step).
- Restore attempted for a pair the server refuses → no retry loop until one end disappears and comes back
  (test in Task 2 via `attempted` set semantics).

**Interfaces:**
- Produces (namespace `v9::pw`):
  - `class DumpStreamSplitter { QList<QByteArray> feed(QByteArrayView chunk); }` — returns every complete top-level JSON array in order; tracks depth outside strings, handles escapes.
  - `struct GraphNode { quint32 id; QString name; QString label; QString mediaClass; bool internal; };`
  - `struct GraphPort { quint32 id; quint32 nodeId; QString name; bool output; bool monitor; };`
  - `struct GraphLink { quint32 id; quint32 outPort; quint32 inPort; };`
  - `class GraphState { bool apply(const QJsonArray &objects); const QHash<quint32,GraphNode>& nodes() const; ports(); links(); void clear(); }` — `apply` returns true if anything changed. Label = `node.description` ?: `node.nick` ?: `application.name` ?: `node.name`. Port name = short form of `port.name` (`playback_FL`→`FL`, `capture_MONO`→`MONO`, `monitor_FR`→`FR`; others unchanged).

### Task 3: PipeWireGraph QObject and QML singleton

**Files:**
- Create: `src/core/PipeWireGraph.h`, `src/core/PipeWireGraph.cpp`; modify `src/core/CMakeLists.txt`
- Modify: `src/app/QmlTypes.h` (singleton `Patchbay`, same pattern as `MixerForeign`), `src/app/main.cpp` (create + assign instance)

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces `class PipeWireGraph : QObject` with:
  - `Q_PROPERTY(QVariantList nodes NOTIFY graphChanged)` — maps `{id, label, kind, internal, x, y, inputs:[{id,name}], outputs:[{id,name}]}`; `kind` ∈ `"playback"` (Stream/Output), `"capture"` (Stream/Input), `"device"`, `"internal"`.
  - `Q_PROPERTY(QVariantList links NOTIFY graphChanged)` — `{id, outPort, inPort, outNode, inNode, internal}`.
  - `Q_PROPERTY(bool available CONSTANT)` (`pw-dump` and `pw-link` found).
  - `Q_PROPERTY(bool restoreLinks READ WRITE NOTIFY restoreLinksChanged)` default false, key `patchbay/restore`.
  - `Q_PROPERTY(QStringList rememberedLinks NOTIFY rulesChanged)` — human text `"Zen FL → Discord MONO"`.
  - `Q_INVOKABLE void connectPorts(quint32 a, quint32 b)` (accepts either order; normalises to out→in; adds rule), `disconnectLink(quint32 linkId)` (removes matching rule), `forgetRule(int index)`, `setNodePosition(quint32 nodeId, qreal x, qreal y)`.
  - Positions in `QSettings` group `patchbay/positions`, key `nodeKey + "#" + occurrence`; unplaced nodes auto-placed: column x = 0 playback/source devices, 320 internal, 640 sinks/capture streams; y stacks by 40 + 30·ports.
  - Restore: on `graphChanged` when enabled, 300 ms single-shot → `missingLinks` → `pw-link` each, add `"out:in"` to `attempted`; erase entries from `attempted` whose ports vanished.
  - `pw-dump` exit → `GraphState::clear()`, emit, restart after 2000 ms.

- [ ] **Step 1:** Implement; build `cmake --build build` → no errors/warnings.
- [ ] **Step 2:** Run app with `QT_FORCE_STDERR_LOGGING=1`, check via a temporary `qCInfo` count that nodes/links match `pw-dump | grep -c` audio nodes; remove the log.
- [ ] **Step 3:** `git commit -m "feature: expose live pipewire graph and link control"`
